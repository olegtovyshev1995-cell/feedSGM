# feedSGM — генератор товарных фидов

Автономный пайплайн выгрузки объявлений (легковые автомобили) на площадки:

```
Google Sheets → валидация → мапперы площадок → XML-фиды → GitHub → площадка забирает фид по raw-ссылке
```

Запуск — по расписанию через **GitHub Actions (cron, раз в сутки)** и вручную.
Это плановый пайплайн: **нет БД, нет HTTP-эндпоинтов, нет сервера 24/7** — так и задумано.

Поддерживаемые площадки:

| Площадка | Лист-источник | Формат фида | Файл фида | Ключ обновления |
|---|---|---|---|---|
| **Avito** (автозагрузка) | `Автозагрузка_авто` | `<Ads><Ad>` | `feeds/avito.xml` | стабильный `Id` |
| **Auto.ru** (легковые) | `Фид (легковые)` | `<data><cars><car>` | `feeds/autoru.xml` | `mark+model+modif+year+color+(VIN/unique_id)` |
| **Drom** (легковые) | `Drom_легковые` | `<avtoxml><Offers><Offer>` | `feeds/drom.xml` | `VIN` или `idOffer` |

## Архитектура

Строгое разделение слоёв — бизнес-логика не течёт в оркестратор:

```
src/
├── config.py         # Pydantic-модели конфига + валидация на старте + require_env
├── sheets_client.py  # чтение листа: таймаут, ретраи с backoff, обработка 403/404
├── validators.py     # падает на битых данных ДО записи фида (со списком строк)
├── build.py          # тонкий оркестратор: конфиг→чтение→валидация→маппинг→атомарная запись
└── mappers/
    ├── base.py       # BaseMapper (абстрактный) + xml_escape/cdata/split_list
    ├── __init__.py   # реестр MAPPERS
    ├── avito.py      # маппер Avito
    ├── autoru.py     # маппер Auto.ru
    └── drom.py       # маппер Drom
```

**Поток данных:** `sheets_client` (данные) → `validators` + `mappers` (логика) → `build.py` (связывание).

Принципы:
- **Новая площадка = один файл-маппер + строка в `MAPPERS` + секция в конфиге.** Оркестратор не меняется.
- Конфиг валидируется на старте (Pydantic). Битый `config.yaml` роняет процесс сразу с понятной ошибкой.
- Логи структурные, в **stderr**; stdout чистый. Корреляция по площадке — префикс `build[avito]` и т.п.
- Ненулевой код выхода при любой ошибке сборки — чтобы CI покраснел.

## Реестр рисков

| # | Риск | Как закрыт | Где |
|---|---|---|---|
| **R1** | Утечка секрета | Ключ только из env `GOOGLE_SA_JSON`; `.gitignore` блокирует `*.json`, `config.yaml`, `sa-key.json`; `config.yaml` собирается в CI из шаблона | `.gitignore`, `config.py:require_env`, workflow |
| **R2** | Битые данные → отклонённый фид | Валидатор роняет билд со списком проблемных строк (номер как в таблице) **до** записи; экранирование `& < >` в мапперах | `validators.py`, `mappers/base.py:xml_escape` |
| **R3** | Нет доступа к таблице | 403 → «выдай Viewer», 404 → «проверь spreadsheet_id / имя листа» | `sheets_client.py:SheetsAccessError` |
| **R4** | Сбой Google API | Таймаут 30с + ретраи с backoff 2→4→8с на 429/5xx; 403/404 не ретраятся | `sheets_client.py:_execute_with_retry` |
| **R5** | Частично записанный фид | Атомарная запись: temp-файл в той же папке + `os.replace`; при ошибке temp чистится | `build.py:atomic_write` |
| **R6** | Неуникальный/меняющийся Id | Id берётся из отдельной колонки (стабильный), в списке обязательных; дубли ловит валидатор | `validators.py`, конфиг `id_column` |
| **R7** | Параллельные запуски | `concurrency.group` в workflow сериализует запуски | workflow |
| **R8** | Пустые коммиты | Коммит только при реальном diff в `feeds/` | workflow |
| **R9** | Зависший job | `timeout-minutes` на job + таймаут на HTTP-запросе | workflow, `sheets_client.py` |
| **R10** | Схема таблицы поменялась | Валидатор проверяет наличие обязательных колонок и падает с понятной ошибкой | `validators.py` |
| **R11** | Задержка cron | Осознанно принято для суточной выгрузки (в workflow — комментарий, что точное время не гарантируется) | workflow |
| **R12** | Схема зависит от категории | Теги = заголовки колонок листа; доп. поля пробрасываются гибко через `column_map.extra`; обязательность взята из шаблонов площадок, не выдумана | конфиг `required`/`extra`, мапперы |

## План внедрения

1. **Google:** выдать сервисному аккаунту роль **Viewer** к вашей Google-таблице (Share → email сервисного аккаунта → Viewer).
2. **Секрет:** положить JSON-ключ сервисного аккаунта в **GitHub Secrets** → `GOOGLE_SA_JSON` (Settings → Secrets and variables → Actions → Secrets).
3. **Переменная:** задать **GitHub Variable** `SPREADSHEET_ID` = ID вашей таблицы (Settings → … → Variables). ID — часть URL между `/d/` и `/edit`.
4. **Листы:** назвать листы как в конфиге (`Автозагрузка_авто`, `Фид (легковые)`, `Drom_легковые`) и заполнить данными по образцу шаблонов.
5. **Проверка:** вкладка **Actions** → `build-feeds` → **Run workflow** (ручной запуск). Убедиться, что job зелёный и в `feeds/` появились/обновились файлы.
6. **Площадки:** указать каждой площадке raw-ссылку на её фид (см. ниже).

## Запуск

### Локально

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# конфиг из шаблона
cp config/config.example.yaml config/config.yaml
#   → впишите spreadsheet_id и, при необходимости, поправьте листы/required

# секрет — только через окружение, не в файлах
export GOOGLE_SA_JSON="$(cat sa-key.json)"

python -m src.build            # соберёт фиды в feeds/
pytest -v                      # тесты
```

### В CI

Автоматически по cron (09:00 МСК) и вручную через **Actions → build-feeds → Run workflow**.

### Raw-ссылки на фиды

После первого успешного прогона фиды доступны по адресам (замените ветку на свою):

```
https://raw.githubusercontent.com/olegtovyshev1995-cell/feedSGM/main/feeds/avito.xml
https://raw.githubusercontent.com/olegtovyshev1995-cell/feedSGM/main/feeds/autoru.xml
https://raw.githubusercontent.com/olegtovyshev1995-cell/feedSGM/main/feeds/drom.xml
```

> Пока работа идёт в ветке `claude/feedsgm-github-repo-tymp9n`, подставляйте её имя вместо `main`.

## Подключение площадок (важно: модель pull, а не push)

Все три площадки **сами забирают** фид по ссылке — вы не «загружаете» файл
скриптом. Автоматизация достигается так: GitHub Actions по cron
пересобирает `feeds/*.xml` → площадка по своему расписанию скачивает
свежую версию по URL. Ссылку регистрируют **один раз**.

| Площадка | Как «загрузка» устроена | Что сделать один раз | Есть ли push-API |
|---|---|---|---|
| **Drom** | Drom опрашивает ваш URL каждые 15–60 мин | Написать на `client@drom.ru`: raw-ссылка + ID кабинета + e-mail для отчётов | Нет |
| **Auto.ru** | `cabinet.auto.ru → Фиды → Автоматическая` — Авто.ру тянет URL | Указать raw-ссылку фида в кабинете | Только партнёрский API (по договору) |
| **Avito** | Автозагрузка: Avito скачивает файл по ссылке 1–2×/сутки | `Кабинет → Автозагрузка → по ссылке` — указать raw-ссылку | Да, Avito Autoload API (нужны `client_id`/`client_secret`) |

**Итог:** для Drom и Auto.ru скрипт-загрузчик не нужен и технически не
предусмотрен — рабочий и валидный фид по URL + cron это и есть полная
автоматизация. Для Avito есть Autoload API: если получите API-доступ
(`client_id`/`client_secret` в кабинете Avito), можно программно обновлять
ссылку и читать отчёты об импорте — по запросу добавим `scripts/avito_autoload.py`.

### Проверка публикации

После сборки полезно убедиться, что фид реально отдаётся по публичному URL
(так его и увидит площадка):

```bash
python scripts/check_feeds.py \
  --base-url https://raw.githubusercontent.com/olegtovyshev1995-cell/feedSGM/main/feeds
```

Скрипт скачивает каждый фид, проверяет HTTP 200, валидность XML и что в нём
есть объявления. В CI этот шаг выполняется автоматически после публикации
(не роняет job — raw-CDN может недолго отдавать кэш).

### Шаблоны листов

Готовые шаблоны для заполнения — в каталоге [`templates/`](templates/):
`avito_autozagruzka_шаблон.xlsx`, `autoru_легковые_шаблон.xlsx`,
`drom_легковые_шаблон.xlsx`. Импортируйте нужный как лист в вашу
Google-таблицу (см. `templates/README.md`).

## Пайплайн обогащения — Фаза 1 (вход → спецификация + фото)

Расширение: Google-таблица содержит **минимум** (VIN, марка, модель), а
заводскую спецификацию **и подтверждённые фото под модификацию** добывает
AI-агент (Claude API + web_search + web_fetch) по встроенному скиллу
`car-spec-researcher`.

Слои (по стандарту backend-developer, всё за интерфейсами/DI):

```
src/
├── pipeline/  models.py (CarInput/PhotoRef/ResearchResult) · ingest.py (Sheets→CarInput) ·
│              state.py (идемпотентность по VIN) · enrich_spec.py (оркестрация+кэш)
├── agent/     claude_client.py (Claude API: web_search+web_fetch, кэш промпта, pause_turn) ·
│              skill_prompt.py (сборка промпта из скилла + контракт вывода) ·
│              card_researcher.py (CardResearcher DI, парсинг спеки+JSON-фото) ·
│              skills/car-spec-researcher/ (встроенный скилл: спека + фотоподбор)
└── enrich.py  entrypoint Фазы 1
data/          specs/<VIN>.md (спеки) · photos/<VIN>/found.json (найденные фото) ·
               state/<VIN>.json (статусы) — кэш в git
```

Скилл возвращает спеку по строгому шаблону (14 блоков) и **JSON-блок с
прямыми ссылками на фото**, у которых доказано 100% соответствие
модификации; пайплайн парсит его и сохраняет `found.json` (вход для C3
imgbb). Ссылки не на файл изображения (страницы-источники) отбрасываются.

**Идемпотентность по VIN:** если вход для VIN не менялся (хэш) и спека есть —
дорогой вызов Claude API **пропускается**. Кэш коммитится в репозиторий,
поэтому переживает эфемерные прогоны Actions.

Запуск:

```bash
export GOOGLE_SA_JSON="$(cat sa-key.json)"
export ANTHROPIC_API_KEY="sk-ant-..."     # только из окружения/Secrets
python -m src.enrich                        # добавьте --force для пересбора
```

Нужны секции `ingest` и `agent` в конфиге (см. `config.example.yaml`) и
секрет `ANTHROPIC_API_KEY`. Модель по умолчанию — `claude-opus-5`
(для экономии можно `claude-sonnet-5` / `claude-haiku-4-5`).

## Диагностика типовых ошибок

| Симптом (в логах stderr) | Причина | Что делать |
|---|---|---|
| `403 Forbidden к таблице …` | Сервисному аккаунту не выдан доступ | Share таблицы → email сервисного аккаунта → **Viewer** |
| `404 Not Found: таблица … или лист …` | Неверный `spreadsheet_id` или имя листа | Проверить `SPREADSHEET_ID` и точное имя листа (регистр, пробелы) |
| `Не задана переменная окружения GOOGLE_SA_JSON` | Нет секрета | Добавить `GOOGLE_SA_JSON` в GitHub Secrets / `export` локально |
| `GOOGLE_SA_JSON не является корректным JSON` | Повреждённый ключ | Скопировать JSON-ключ целиком, без обрезки |
| `Отсутствуют обязательные колонки: …` | Изменилась шапка листа (R10) | Вернуть колонки или поправить `required`/`header_row` в конфиге |
| `Строка N: пустое обязательное поле '…'` | Пустая ячейка в обязательном поле (R2) | Заполнить ячейку в строке N (номер — как в таблице) |
| `Строка N: дубль Id=…` | Повторяющийся Id (R6) | Сделать Id уникальным |
| `Конфиг … не прошёл валидацию` | Ошибка в `config.yaml` | Сверить с `config.example.yaml`, см. текст ошибки |
| Job красный, но фиды не изменились | Ошибка сборки у одной из площадок | Открыть лог шага **Build feeds**, найти префикс `build[<площадка>]` |

## Как добавить площадку

Например, ЦИАН:

1. Создать `src/mappers/cian.py` — класс `CianMapper(BaseMapper)` с `platform = "cian"` и методом `build_xml(records)`.
2. Дописать одну строку в `src/mappers/__init__.py`:
   ```python
   from src.mappers.cian import CianMapper
   MAPPERS[CianMapper.platform] = CianMapper
   ```
3. Добавить секцию в `config.example.yaml` (`name: cian`, `sheet`, `header_row`, `data_start_row`, `id_column`, `output`, `required`).
4. Добавить тест в `tests/test_pipeline.py` (валидный XML + экранирование).

Оркестратор (`build.py`), валидатор и клиент Sheets при этом **не меняются**.

## Границы (честно)

- Точную схему справочников Avito/Auto.ru/Drom под конкретную модель мы не выдумываем — теги строятся по заголовкам ваших листов и шаблонам площадок. Для Drom числовые `id*`-поля требуют `ref.xml`; по умолчанию используются текстовые `s*`-поля (марка/модель/город текстом).
- Корректность значений (реальные цены, наличие, соответствие справочникам площадок) — вне зоны валидатора: он ловит только пустоту и структуру.
- Мапперы ЦИАН и др. пока не реализованы — есть интерфейс, чтобы добавить их по образцу.
